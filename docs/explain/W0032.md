# W0032 — an in-out out-arg cannot be colon-bound

An out-param that **shadows an in-param** (the same name in both lists) is the *in-out* form: the caller's
place goes in and comes back out. That is how a `#foreign` extern declares a buffer it fills, and it is
what makes a mutated in-param safe to pass without `own` (see `W0011`, `W0012`).

At the call site an in-out is written by naming the **existing place**, with `_` marking the in-slot it
came from:

```arche
fill(3, _)(b);      // b goes in and comes back
```

`(name:)` means something different: *declare a new local and bind the out into it*. An in-out has no new
place to declare — its value **is** the in-arg's place — so the binding names nothing. Before this
diagnostic existed the reference simply had no value: it lowered to the constant `0` and the program built
and ran with a plausible wrong result.

That is exactly how the `window_open` example in `docs/language.md` stayed broken for so long:

```arche
window_open :: proc(own title: []char, w: int, h: int)(w: window);   // BAD: `w` is width AND window
```

`w` is the *width* in the in-list and the *window* in the out-list, so the out silently became an in-out of
an unrelated `int`, `window_open("demo", 640, 480)(w:)` bound nothing, and `0` was passed onward as the
window handle. The fix there was to name the in-params `width`/`height` — the out `w` is then a genuine
out-only param, and `(w:)` is the right way to bind it.

This does **not** depend on the two types differing. A same-type shadow (`[]char` in, `[]char` out) fails
identically — the trigger is the colon on an in-out out-arg, not the types.

## Fixing it

- **Writing an in-out**: name the existing place and mark the in-slot — `fill(3, _)(b)`.
- **You meant a fresh output**: the out-param should not share an in-param's name. Rename the in-param, and
  the out becomes out-only.

## Severity

W0032 is an **error by default**: the construct has no valid reading, and its old behaviour was a silent
wrong value rather than a diagnostic. Suppress a single site with `@allow(inout_outarg_colon_bind)`.

## Example

```arche
#foreign {
  fill :: proc(n: int, buf: []char)(buf: []char);   // in-out: `buf` in both lists
}

run :: system eff {
  b: [8]char;
  fill(3, _)(b);        // GOOD — writes the existing place
  // fill(3, b)(nb:);   // W0032 — nothing to declare; `nb` would name no value
}
```

See `W0011` (in-out call repeats the in-slot) and `W0012` (in-out param shadow on a non-foreign proc).
